## [Unreleased]

### Added

- **`.agent/personal/` now reaches the model only when you say so, per call.** `dreamd dream --share-personal` (and `x-dreamd-share-personal: 1` on `POST /api/v1/dream`) is the whole consent surface; without it the dream-cycle composition prompt is the promoted cluster and nothing else. The default is enforced by construction rather than by filtering: `build_lesson_prompt` is never handed the store, so it cannot reach `personal/` whatever is in it, and the opted-in bytes are appended by `compose_lesson_body` *after* that call and *before* `estimate_prompt_cost` — so the cluster prompt stays cluster-only and the AILAB-196 cap prices the string actually about to be sent, not a shorter one. The reader takes regular UTF-8 files directly under `personal/`, ordered `PREFERENCES.md`, `DECISIONS.md`, then the rest by name; it does not walk subdirectories, skips non-UTF-8 files with a `WARN`, and refuses a symlink whose target resolves outside `personal/` rather than following it into `~/.ssh`. Output is capped at the same 16 KiB `GET /api/v1/preferences` truncates at — one constant now, re-exported by that handler rather than restated, so an oversized `personal/` cannot push an otherwise-affordable cycle over `cost_cap_usd` as a side effect of opting in. Every cycle that actually attaches bytes emits a `WARN` naming `share-personal` and `personal/`, so a disclosure is a line in the log rather than a silence; a boot-time banner was rejected because one that fires when nothing was shared trains the operator to ignore exactly this line. Consent is **per call and never sticky** — no config key, no environment variable, no persisted state. `--share-personal` travels *through* the daemon proxy as a header for the same reason `--no-llm` does (the daemon is the single writer of the episodic log); `--dry` still skips the proxy and therefore takes the flag in-process, because a preview that dropped it would show a prompt the real cycle is not going to send. `--no-llm --share-personal` is legal and discloses nothing: with no backend there is no request to consent to, and `personal/` is not read at all. Personal bytes are prompt context only — the cycle still never distills `personal/` into `semantic/`, the AILAB-200 citation trailer still names only episodic `evt_` ids, `GET /api/v1/preferences` is still ungated (it serves the local agent, not a model), and `VERSIONED_PROMPT_ID` stays `dream-cycle/v1.2@2026-08-23` with `prompts/v1.1.txt` unchanged. `MemoryCoordinatorMsg::RunDreamCycle` gains a **required** `share_personal` field rather than a defaulted one, so a new message site that forgets it fails to compile instead of quietly disclosing. (AILAB-199 — `crates/dreamd-core/src/llm.rs`, `dream_cycle.rs`, `coordinator.rs`, `client.rs`, `server/http/handlers/dream.rs`, `crates/dreamd-cli/src/cli.rs`, `commands/dream.rs`)

- **`cost_cap_usd` is now enforced before the model call rather than after the bill.** `dreamd dream` prices the composition prompt with `tiktoken-rs` (the bundled `cl100k_base` encoding) immediately after `build_lesson_prompt` and before any HTTP call, adding a 512-token output reserve at the model's published output rate; if the estimate exceeds `cost_cap_usd` (default `$0.10`) the backend is never invoked — the cycle emits a `cost estimate exceeds cap` `WARN` carrying `estimated_usd`, `cap_usd`, `input_tokens`, and `model`, and writes the deterministic exemplar body instead, so an over-cap cycle degrades exactly like a missing API key rather than failing. The estimate lives at the call site, not inside the genai client: counting inside the client would re-count the same prompt on every retry attempt, and would put the one decision worth unit-testing behind a backend. An unknown model id has no price in the table and is treated as over cap, and `cost_cap_usd = 0.0` always aborts, so every unknown fails toward *not spending money*. `dreamd doctor --cluster-health` now reports the same number ahead of time as `cluster_health: next_cycle_est_usd=…`, computed through the `--dry` preview seam so the check writes no `LESSONS.md`, no `recurrence_counts.json`, and no WAL. `cl100k_base` is knowingly the wrong tokenizer for Claude — roughly ±25% on prose of this shape, so real spend can reach ~$0.13 against a $0.10 cap — which is documented rather than corrected, because the alternatives were a network round trip to decide whether to make a network call or a vendored copy of a tokenizer Anthropic does not publish. See [docs/llm-cost-accuracy.md](docs/llm-cost-accuracy.md). (AILAB-196)

- **`dreamd dream --dry` now previews the cycle instead of rejecting it.** It prints the `.agent/semantic/LESSONS.md` this cycle *would* write to stdout — the exact bytes, rendered through the same serializer the writer persists with — and exits 0 without touching `.agent/`. Nothing promotes? Stdout stays empty and stderr says the cycle would *retire* `LESSONS.md` (AILAB-699); the existing file is left on disk, because a preview that unlinked the file it is previewing the removal of would be a write. No WAL is opened, no `recurrence_counts.json` is written, the episodic log is not rewritten, no index is opened, and no autobiography commit is made. `--dry` is the one dream path that **skips the daemon proxy** — `POST /api/v1/dream` performs the mutation the flag exists to avoid — which is the exact inverse of `--no-llm`, which must travel *through* the proxy as `x-dreamd-no-llm: 1` so the daemon stays the single writer. `--no-llm` still forces the deterministic exemplar body on the preview; without it the preview may call the model, since comparing composed prose against the raw JSONL is the point of the flag. `--no-commit` alongside `--dry` is ignored rather than rejected: with no writes there is no commit to skip. `--dry --auto` remains invalid and `--auto` alone still exits 2.
- **LLM-composed lessons must now cite the events they were composed from.** The dream-cycle prompt asks the model to end its answer with one trailer line — `citations: evt_… evt_…` — and `dreamd-core` parses **only that line**, requiring every id to be a real member of the promoted cluster. Scraping `evt_` ids out of the prose was rejected: a lesson that merely *mentions* an id would have passed the gate this exists to be, and would have pinned events the model never claimed to have used. A missing, malformed, or hallucinated trailer is treated exactly like a transport failure — structured `WARN`, then the deterministic exemplar copy — so a model that cannot cite still never fails a cycle. `.agent/semantic/LESSONS.md` frontmatter gains a file-level `citations: "evt_a evt_b"` key (space-separated inside one quoted scalar, the only shape the frontmatter reader has ever understood); files written before this change have no such key and still parse, reading back as an empty list. `apply_pin_unpin` now pins the **union** of every `Lesson.id` and every frontmatter citation, so a cited cluster member that is not the exemplar survives decay instead of being pruned out from under the lesson that rests on it. The deterministic arm writes `citations` = the exemplar id, which leaves `--no-llm` pin behavior byte-for-byte unchanged and makes an LLM fallback byte-identical to a deterministic cycle. `Lesson.id` is still always the exemplar's `evt_` id — no ids are minted. The prompt id moves to `dream-cycle/v1.2@2026-08-23`: the last rule of `crates/dreamd-core/src/prompts/v1.1.txt` was rewritten in place, so the file name stays while the id moves — one prompt file can back several ids, and the id must move in the same commit as the bytes or frontmatter starts lying about its own provenance. The token cap (AILAB-196) and personal-layer redaction (AILAB-199) remain out of scope. (AILAB-200 — `crates/dreamd-core/src/llm.rs`, `dream_cycle.rs`, `lessons.rs`, `consolidation.rs`, `prompts/v1.1.txt`)

- **LLM-composed dream-cycle lessons when an API key is present.** `dreamd dream` / `POST /api/v1/dream` call `genai` 0.6 (default model `claude-haiku-4-5`) and write the model's prose as `Lesson.content` with `prompt_version: llm-unversioned`. Missing credentials, `--no-llm`, or a failed/empty completion after 3×30s retries fall back to the deterministic exemplar copy and log `no API key — falling back to --no-llm`. `--no-llm` travels as `x-dreamd-no-llm: 1` through the daemon proxy; it does not skip it. Credentials: env (`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`) then `~/.config/dreamd/secrets.toml` mode 0600. `cost_cap_usd` stays unread (AILAB-196). (AILAB-204)

- **`dreamd doctor` now names lessons the semantic pass could not index.** A lesson whose exemplar event is missing from the episodic log is skipped rather than indexed — indexing it without the exemplar's pain/importance would add a document that scores exactly 0.0 and can never rank — so the lesson is simply absent from recall with nothing to distinguish it from an unlucky query. The pass now records the skipped `lesson.id`s and their `cluster_key` to `<project>/.agent/.dreamd/semantic_pass.json`, and `doctor` reads that sidecar and emits one `semantic_lessons: N not indexed [WARNING: …]` line naming the count, the first id, the cluster, and the likely cause (an unpinned or archived exemplar), setting exit 1. A sidecar rather than a doctor-side recomputation: re-resolving `LESSONS.md` against the JSONL would be a second parser for the same rule, and doctor is most valuable when the daemon is down, so the read opens no index and takes no lock — the same shape as the shipped `IndexProgress` → `assess_index_freshness` path. The write lives inside `index_semantic_lessons`, so both consumers (the `TantivyIndexHandle::open` rebuild, which also serves cold start and `doctor --repair`, and the live indexer task's post-consolidation pass) produce it. Writing on the **zero-skip** path is load-bearing: without it a store whose exemplars were restored would keep reporting yesterday's skips forever. The retirement path (AILAB-699's absent `LESSONS.md`) writes an empty record for the same reason, while a **malformed** `LESSONS.md` writes nothing at all — it left the index untouched, so the prior record is still the truth about what is in it. Zero skips or an absent sidecar print nothing; a healthy store stays quiet. An **unreadable** sidecar — present but unparseable — reports `semantic_lessons: unreadable [WARNING: …]` and also sets exit 1: doctor cannot answer the question it was asked, and a silent pass there is indistinguishable from a clean one, the same posture `index_freshness`'s error arm already takes. `SemanticPassOutcome` is unchanged (it is `Copy` and crate-private), the record carries no timestamp (doctor reports current state, not when it was measured), and `index::SCHEMA_VERSION` is untouched — this is a plain JSON file, not the Tantivy schema. (AILAB-700 — `crates/dreamd-core/src/server/tantivy_handle.rs`, `crates/dreamd-core/src/server/mod.rs`, `crates/dreamd-cli/src/commands/doctor.rs`)

### Changed

- **The workspace release profile now builds with fat LTO.** `[profile.release]` in the root `Cargo.toml` sets `lto = "fat"` and `codegen-units = 1`. NFR-2 (stripped `dreamd` ≤ 20 MB) was already red on `main` at ~20.5 MB under the default profile — the 16.77 MB figure in the AILAB-204 entry below was never the CI number — and linking a tokenizer on top of that would only widen the gap. Fat LTO dead-strips the encodings nothing reaches and brings the stripped binary back under the gate *with* the estimator live, so this is a shrink, not a raised gate: `MAX_BYTES` stays at 20 MB. `panic = "abort"` was deliberately not set (it would change unwind behavior) and `strip` stays a CI step rather than a profile key. The cost is longer release builds. (AILAB-196)

- **MCP `search_nodes` / `append_node` descriptions now distinguish episodic events from semantic lessons, with no new tool params.** After AILAB-205 made recall blend both layers, the shipped copy still said "Search episodic memory", so an agent reading the tool list had no way to know a hit might be a consolidated lesson — and no vocabulary for the `source` field already present on every hit. The three-element progressive-disclosure rewrite keeps the AILAB-357 v1 trigger phrases verbatim (`recall`, `did we discuss`, `what did we decide`, `previously decided` / `note that`, `remember`, `log this`, `save this lesson`) and adds one sentence naming `source=episodic` vs `source=semantic` and stating outright that **there is no layer argument** — agents were otherwise liable to invent one. `SearchNodesParams` is unchanged (`query` + `k`); `crate::recall(..., None)` is unchanged; the HTTP `q` parameter keeps its own name. `append_node`'s copy now names its real write target, `AGENT_LEARNINGS.jsonl`, and disclaims `.agent/semantic/LESSONS.md`, which only the dream cycle writes — the old "save this lesson" trigger read as though the tool wrote lessons directly. rmcp 1.7 parses `#[tool(description = ...)]` as a darling `Option<String>`, so the attribute takes a string literal and cannot reference a const; the bytes therefore live in `SEARCH_NODES_DESCRIPTION` / `APPEND_NODE_DESCRIPTION` with the literals duplicated into the unix and `not(unix)` `search_nodes` attributes, and a test compares the macro-generated `Tool.description` back to each const so the copies cannot drift. `get_info` server instructions gain one WHEN TO CALL bullet naming the same field (and the opening line now reads "agent memory (events + lessons)") so the two MCP surfaces do not contradict each other; `skill_action`, SCORES, `client_dedup_key`, and DO NOT STORE are byte-identical. Description strings only — no behavior, wire-format, or schema change. (AILAB-191 — `crates/dreamd-core/src/mcp/mod.rs`)

- **LLM-composed lessons now stamp a versioned prompt id.** `.agent/semantic/LESSONS.md` frontmatter carries `prompt_version: dream-cycle/v1.1@2026-08-23` on the LLM arm, superseding the throwaway `llm-unversioned` id the AILAB-204 entry above describes. The instruction block moved out of the `UNVERSIONED_LESSON_PROMPT` string literal in `llm.rs` into `crates/dreamd-core/src/prompts/v1.1.txt`, bundled at build time by `include_str!` — an installed `dreamd` has no source tree to read from, so the bytes ship inside the binary and a prompt can never go missing at run time. **The prompt wording is unchanged**: the file is a byte-for-byte move plus the POSIX trailing newline every text file in the tree carries, which widens the gap before `Cluster:` in the assembled prompt from one blank line to two and changes nothing else. The date in the id is the **bundle** date of those bytes, not the cycle date, so a lesson's frontmatter names the prompt that produced it rather than the night it ran; a unit snapshot makes an edit to the file loud in review, but moving the id remains a reviewer's job, not something the harness enforces. Existing `LESSONS.md` files keep their old `llm-unversioned` value and still parse — `prompt_version` is a free-form string that is read back and rewritten, never validated against a known set — so no migration is needed and no lesson is re-composed. The deterministic arm still stamps `prompt_version: "deterministic-only"` and is untouched. Citation validation (AILAB-200), the token cap (AILAB-196), and personal-layer redaction (AILAB-199) remain out of scope. (AILAB-201 — `crates/dreamd-core/src/llm.rs`, `crates/dreamd-core/src/dream_cycle.rs`, `crates/dreamd-core/src/prompts/v1.1.txt`)

- **NFR-2 stripped-binary gate raised from 15 MB to 20 MB.** `genai` 0.6.5 (AILAB-204) lands the Linux stripped `dreamd` at 16.77 MB; main had ~0.81 MB of headroom under 15 MB. Soft warning moved 12 MB → 16 MB. Enforced in `.github/workflows/ci.yml` and `release.yml`. (AILAB-204)

- **Opening a secondary project's Tantivy index no longer holds the `index_map` mutex.** `AppState::with_index_handle` took the map lock and then called `map.get_or_open(root, |r| TantivyIndexHandle::open(..))`, so the open — a full JSONL replay, a Tantivy commit, and a 50 MB `IndexWriter` allocation — ran inside the guard. Every other project's recall, learn, and dream stalled behind it, because `index_map` is one lock for all non-primary roots. The lock could not simply be narrowed in place: `get_or_open` returns `&mut H` **borrowed from the map**, so the borrow is live for as long as the caller uses the handle and the open must happen while it is held. The map API is therefore split into halves that can straddle a lock release — `ProjectIndexMap::get_handle` (lookup only, marks MRU, `None` on a miss) and `insert_or_adopt` (publish an already-opened handle) — and `with_index_handle` now runs lookup → **release** → open → re-lock → publish, with the open the only statement between the two guards. `get_or_open` is retained unchanged for its three existing callers; both new methods share one `promote` helper with it so the hit-path LRU bookkeeping cannot drift. Releasing the lock makes two first-touches of the *same* root race, and `insert_or_adopt` settles that: **the incumbent wins** — by the time a handle is in the map it may already have handed its `IndexReader` or indexer `Sender` to live requests, and `supervisor_map` caches per-root coordinators wired to that very channel, so replacing it would strand all of them — and the loser is **closed**, not dropped silently, since two live handles on one index directory means two `IndexWriter`s. The losing *open* can also fail outright rather than produce a handle, because Tantivy's per-directory writer lock is non-blocking; that arm re-checks the map before surfacing the error, preserving the old shape's outcome (block, then find the winner's handle) instead of turning a rare race into a 500. `spawn_blocking` was deliberately **not** used: the AC is about the mutex and cross-project blocking, both of which the restructure achieves on its own — the daemon runs a multi-thread runtime, so other workers keep serving while one blocks in the open — and wrapping it would make `with_index_handle` `async` and ripple through every caller for no additional guarantee. The pinned-primary fast path, `TantivyIndexHandle::open` itself, and the eviction policy are untouched. (AILAB-186 — `crates/dreamd-core/src/server/http/state.rs`, `crates/dreamd-core/src/server/index_map.rs`, `crates/dreamd-core/src/server/project_resource_map.rs`)
- **Public docs now match shipped 0.1.0 behavior.** Status/GA dates, npm vs cargo CLI invocation (`npx -y dreamd-mcp` does not put `dreamd` on `PATH`), MCP Remote stderr strings, dream-cycle top-cluster + salience-first exemplar, `DREAMD_SOCK`/`DREAMD_LOG`/`DREAMD_BIN` operator facts, live `pinned`, and the `docs/dreamd.1` man page (generator now writes that path). Docs and man-page generator only — no binary behavior change.

### Fixed

- **A mid-file blank or malformed line in `AGENT_LEARNINGS.jsonl` is now excised into a dated quarantine sidecar instead of sitting in the live log forever.** WEG-378 already stopped mid-file corruption from truncating the file — `episodic::scan` skips a blank or schema-invalid `\n`-terminated line and keeps going, so the records *after* the hole were never lost. What it did not do was remove the hole: `recover` only ever `set_len`'d a torn final line, so the bad bytes stayed in the log and every later `read_all` re-parsed them, re-warned about them, and re-skipped them. Open-time `episodic::recover` now takes the log's path, and when the scan reports skips it appends those raw lines verbatim to `<episodic dir>/.corrupt-<YYYY-MM-DD>.jsonl` (UTC, `0600`, appended to rather than clobbered on a same-day second recovery), then rewrites the live file to the well-formed record stream. The rewrite deliberately does **not** go through `rewrite_atomic`: the coordinator holds that fd open across the call, so swapping in a fresh inode would send every subsequent append into an unlinked file. It is `seek(0)` → `write_all` → `set_len` → `sync_data` on the caller's own descriptor. Only the skipped lines are quarantined — not the suffix from the first anomaly onward — so a valid record sandwiched between two bad ones stays in the live log. A torn tail with no mid-file skips still takes the old path exactly: `set_len`, `debug!`, no sidecar. A quarantine logs once at `warn!` with the log path, the sidecar path, and the skip count, because bytes moved out of the live log and the operator should be able to find them. The DR-103 write path is untouched; this is open-time recovery only.
- **A live `IndexerMsg::Append` is no longer dropped when the indexer channel is full.** After each durable JSONL write the coordinator handed the append to the indexer with a non-blocking `try_send`, and on `TrySendError::Full` it threw the message away, logging a warning that called the drop recoverable by the next startup replay. That claim was false. `replay_two_pass` re-indexes events whose `id > last_indexed_id`, and `last_indexed_id` is the newest **committed** id, not a contiguous prefix — so a shed event N followed by any indexed event N+1 moves the watermark past N and skips it forever. Only a shed *tail* with nothing newer behind it ever replayed; a middle gap was permanent silent loss from recall, while `POST /api/v1/learn` still answered 201. `handle_append` is now `async` and `route_to_indexer` (renamed off `try_`) **awaits** `tx.send(msg)`, so a full channel backpressures the coordinator instead of shedding: the actor stops reading its own inbox, in-flight learns queue in the 256-slot coordinator channel and simply *wait* — no per-request timeout sits on the response — and only once that inbox is full too does the separate 100 ms `COORDINATOR_SEND_TIMEOUT` return an honest HTTP 503 rather than a 201 for a record recall will never see. So a brief park surfaces as latency and sustained overload as 503, and that 503 is the **HTTP** ingress only: the in-process `dreamd mcp` path sends on the coordinator channel without that timeout, so it waits. The channel stays bounded at `DEFAULT_INDEXER_CHANNEL_CAPACITY = 1024` and the commit cadence stays 5 s — the append is acked when the indexer *accepts* the message, not when Tantivy commits. `Closed` is unchanged: warn once, drop the sender, live indexing stops until restart. Startup replay now only ever heals the tail after the watermark (a crash between JSONL `sync_data` and the next commit), which is all it was ever able to do. Saturation is still a *cause* of staleness — a queued append is in the JSONL and not yet committed, so `assess_index_freshness` reports `stale` while the backlog drains — it just no longer persists until a restart. (`crates/dreamd-core/src/coordinator.rs`, `crates/dreamd-core/src/server/tantivy_handle.rs`, `crates/dreamd-core/src/server/watch.rs`, `crates/dreamd-core/src/server/lifecycle.rs`)
- **The post-signal drain in `dreamd watch` is now capped at 30 seconds.** AILAB-162's shutdown drain awaited `drain_daemon` with no deadline, so a `Shutdown` queued behind an in-progress dream cycle (or a `Flush` behind a recurrence sidecar apply) could hold the exiting process for as long as that work took — and with the `select!` loop already exited, a second SIGTERM was swallowed, leaving SIGKILL as the only way out. The call site now wraps the drain in `with_drain_timeout(DRAIN_TIMEOUT, …)` (`tokio::time::timeout`, 30s); on elapse it logs a warning and `run_watch` exits anyway — best-effort, the same posture as a failed flush, since the JSONL append is already durable and a lost final commit costs a rebuild on next open, not data. The socket unlink still runs *before* the drain, so the WEG-268 no-stale-socket guarantee never waits on it, and `drain_daemon` itself is unchanged — the bound lives at the `run_watch` call site only. (AILAB-748 — `crates/dreamd-core/src/server/watch.rs`)
- **`dreamd watch` now drains the coordinator and the index before it exits, instead of only unlinking its socket.** Half of graceful shutdown already shipped: SIGTERM is armed alongside SIGINT in `run_watch`'s `select!`, and both arms unlink `~/.agent/dreamd.sock` so a service-managed daemon leaves nothing stale behind (WEG-268). The other half was never wired. After the `select!`, `run_watch` unlinked the socket and returned — it called neither `Supervisor::shutdown` nor `TantivyIndexHandle::shutdown`, and an inline comment deferred "the full coordinator/indexer drain" to WEG-283. So the indexer's accumulated batch was still uncommitted when the process exited, and an append the coordinator had queued but not yet reached was lost. `Supervisor::shutdown` existed and was tested but had **zero production call sites**, because it cannot be reached from `run_watch`: it takes `self` by value, while `AppState::supervisor` is an `Arc<Supervisor>` and `state` is moved into `build_router` before the signal loop begins — after that move, an `Arc::try_unwrap` here races every live connection task. `run_watch` therefore clones the supervisor `Arc` and the primary index `Arc` **before** the move, and a new `Supervisor::drain(&self)` performs the drain through a shared reference: it sends `MemoryCoordinatorMsg::Shutdown` and awaits the acknowledgement. What that does and does not guarantee is worth stating exactly, because the coordinator's `Shutdown` arm is `rx.close()` followed by a receive-and-*discard* loop: everything queued **ahead of** `Shutdown` is handled normally by the main loop and lands on disk, while anything a still-live connection task enqueues **behind** it is dropped. That window is not new — it is why `shutdown(self)` documents "drop every issued sender before calling" as a MUST — and `drain` neither widens nor closes it, because `run_watch` has no way to join axum's spawned per-connection tasks. `drain` relaxes the *liveness* requirement only: it completes with senders outstanding, where `shutdown` would block. `shutdown(self)` is unchanged in behavior and still joins the task; it now delegates its first half to `drain` and remains the path every test uses. **Order is load-bearing — coordinator first, then index:** `Supervisor::start` is handed `primary_handle.sender()`, so the coordinator owns a clone of the indexer channel, and flushing first would commit a batch the coordinator was still adding to. Which index arm runs depends on who still holds the handle: `tokio::select!` drops the losing `serve_uds` future along with the router and its `AppState`, so on an **idle** daemon — the ordinary `systemctl stop` — `Arc::try_unwrap` succeeds and `TantivyIndexHandle::shutdown` awaits the indexer task's own final commit; while a spawned connection task is still in flight the unwrap fails and a promoted `TantivyIndexHandle::flush` runs instead. Both arms are covered by tests that assert which one they are driving, so a later edit cannot silently swap them. `flush` is the existing test-only helper made `pub(crate)` rather than a new commit path: it rides `IndexerMsg::Flush` and awaits the same `commit_and_persist` every other commit goes through, and no `IndexerMsg::Shutdown` variant was added. `IndexHandle::close` is deliberately not used on either arm — called from inside a runtime it `abort`s the indexer task and loses exactly the batch the drain exists to save. The socket unlink now runs **before** the drain rather than after: the drain has no deadline, a `Shutdown` queued behind an in-progress dream cycle takes as long as that cycle does, and sequencing a shipped guarantee behind an unbounded await would let systemd's `TimeoutStopSec` SIGKILL strand the socket — the ticket requires only that the drain precede process exit. Both index arms are best-effort and log rather than propagate: the process is exiting, the JSONL append is already durable, and a lost commit costs a rebuild on next open, not data. The drain is split into a `pub(crate) drain_daemon` so the ordering contract is unit-testable without binding a socket. Deliberately out of scope: `supervisor_map` and `index_map` entries, which stay drop-reap (AILAB-306); any timeout, heartbeat, refcount, or grace window (AILAB-210); `MemoryCoordinator::run`, which is untouched; and Windows signal handling. (AILAB-162 — `crates/dreamd-core/src/server/watch.rs`, `crates/dreamd-core/src/server/lifecycle.rs`, `crates/dreamd-core/src/server/tantivy_handle.rs`)
- **The dream cycle no longer eats the autobiography skip marker it is supposed to explain.** `wal.rs` did not patch `state.json`, it *rebuilt* it: `update_state_json` read back exactly one key (`schema_version`), then emitted a fresh four-key `serde_json::json!` object and `write_atomic`'d it over the file. Every key it did not know about was dropped — and `last_autobiography_skip`, written by `autobiography.rs` when a dirty tracked tree holds back the audit-trail commit, is exactly such a key, so `dreamd doctor` lost the only record of *why* the commit had not happened. Both cycle edges were eaters, not just `begin_cycle` as the ticket described: `commit_cycle` runs the same from-scratch writer on the way out, so a marker written mid-cycle died at the far end too, and both `recover_if_needed` arms did the same on startup. The `cycle_at: None` argument compounded it — `None` serialized as JSON `null`, not "leave unchanged", so every `begin_cycle` also wiped the *previous* cycle's `last_dream_cycle_at`, and a store that had completed a cycle reported no completion time the moment the next one started. `state.json` is now a typed `DaemonState` behind one read-modify-write writer, `update_daemon_state`, which takes a closure patch so a field the caller does not name round-trips off disk: `begin_cycle` and both recover arms patch **status only**, and `commit_cycle` alone assigns `last_dream_cycle_at`. The types live in a **new** `daemon_state.rs` rather than in `wal.rs`, because `DaemonState` needs `Option<AutobiographySkip>` while both writers need the writer — keeping either half in its current home is a `wal → autobiography → wal` compile cycle; `AutobiographySkip` moved there and is re-exported from `autobiography`, and `STATE_SCHEMA_VERSION` moved there and is re-exported from `wal`, so `crate::wal::STATE_SCHEMA_VERSION` and `autobiography::AutobiographySkip` stay valid paths for `migrate.rs`, `doctor.rs`, `cli.rs`, and `setup.rs`. The version stays `"1.0"`: adding an optional field is backward compatible, and a bump would strand every store written before it. Field **declaration order is alphabetical** and load-bearing — `#[derive(Serialize)]` emits declaration order while the old `json!` writer emitted `serde_json`'s BTreeMap ordering, so the five fields are declared in that order to keep `dream_cycle_snapshot__state_json.snap` byte-identical rather than re-recorded. Skip-absent semantics are unchanged: `#[serde(skip_serializing_if = "Option::is_none")]` **omits** the key exactly as the old `Map::remove` did, never writing `null`, because doctor's reader distinguishes the two. `read_last_cycle_status` / `read_cycle_started_at` / `read_last_skip` stay `Value`-based and type-tolerant — they are readers, and a hand-edited `state.json` should not start erroring. Deliberately out of scope: `init.rs`'s private `State`, which is a create-only scaffold writer and never rebuilds an existing file, and a flatten-unknown-extras bag or `deny_unknown_fields`. Unknown keys are dropped on read-modify-write, which is what `wal.rs` already did on every cycle edge — but note this does narrow `autobiography.rs`, whose `Value` RMW preserved keys it did not name. Nothing in-tree writes such a key and the next cycle edge ate it regardless, so no live behavior changes; preserving unknown keys across writers is a different product decision and not this ticket's. It is now a `thiserror` enum — `ChannelClosed`, `TaskDropped`, `LockPoisoned`, `Wal`, `Supervisor`, `Io`, `Tantivy`, `TantivyDirectory`, `Other` — with `is_retryable()` true for exactly the two channel variants. ### Fixed

- **`uninstall` / `update` no longer stop other homes' (or other users') dreamd servers.** Both commands stopped local servers by shelling out to the manual README recipe's bare `pkill -f 'dreamd mcp'` / `pkill -f 'dreamd watch'`, which is machine-global by construction: it SIGTERMs every process on the box whose command line matches, whatever `$HOME` it serves. The 2026-08-03 clean-box audit caught it (AILAB-554 F1) — a sandboxed `HOME=/tmp/… dreamd update` killed the developer's real Cursor `dreamd mcp`. An empty `HOME` is now treated as no home at all, since `$HOME/.cache/dreamd-mcp` would otherwise collapse to a cwd-relative path that attributes foreign processes (and, in `uninstall`, a cwd-relative `./.npm/_npx` the scoped cache clear would *delete*). The `packages/dreamd-mcp` manual recipe no longer teaches the unscoped kill. (AILAB-584 — `crates/dreamd-cli/src/commands/lifecycle_cleanup.rs`, `cli.rs`, `uninstall.rs`, `update.rs`, `packages/dreamd-mcp/README.md`, `scripts/alpha/install-funnel-suite.sh`)
- **`uninstall` / `update` no longer unlink a live daemon's socket.** Both commands run a best-effort `pkill` stop pass whose failure is only a stderr warning, so on a box without `pkill` — or where the signal is denied — the daemon was still serving when its socket file was removed. That orphaned it: the daemon kept working while every client resolved a path that no longer existed, so MCP silently fell back to the in-process Phase 1 backend and cross-harness recall stopped with no error. `remove_socket` now connect-probes first and leaves a live socket in place with an actionable warning, matching the rule `dreamd archive` and `dreamd doctor --repair` already apply. Because `pkill` returns when the signal is *delivered* rather than when the target exits — and `dreamd watch` drains its coordinator and Tantivy indexer before unlinking its own socket — the probe waits out a 5s grace window first, so a daemon that is merely mid-shutdown is not mistaken for one that refused to stop. (`crates/dreamd-cli/src/commands/lifecycle_cleanup.rs`, `uninstall.rs`, `update.rs`)
- **A healthy index is no longer wiped by a false schema-mismatch match.** `is_schema_incompatible` gates a `remove_dir_all` of the index cache but matched a bare `"schema"` substring anywhere in the error text. `tantivy_io_to_index` embeds the *directory path* in its message, so any store living under a path containing "schema" (e.g. `~/dev/schema-tools/`) tripped the branch and silently rebuilt a healthy index. The companion `|| msg.contains("incompatible")` alternative was removed: `TantivyError::IncompatibleIndex` renders through `Incompatibility`'s hand-written `Debug` as `"Library version: N, index version: M. …"`, so it never matched that variant and only widened the false-positive surface — an index-*format* mismatch stays a loud startup error rather than a silent wipe. (`crates/dreamd-core/src/server/tantivy_handle.rs`)

- Self-healing index rebuild on schema-version mismatch: `TantivyIndexHandle::open` wipes and replays the JSONL under the current schema when an on-disk index predates the binary, on both the daemon and no-daemon paths (WEG-424).

### Changed

- Learn responses (`POST /api/v1/learn` and MCP `append_node`) now return a daemon-minted `timestamp` from the coordinator, matching the `EventId` overwrite rule; client-supplied timestamps in the request body are ignored on success.
- Tantivy index schema bumped `index/1.2` → `index/1.3` (adds the `skill_action` + `source_harness` STORED fields). Existing indexes rebuild automatically from the JSONL on first open.

- `dreamd version` — structured version output block with build metadata.
- `dreamd doctor` — health-check output (dream-cycle mode and state-surface diagnostics).
- `dreamd init --uninstall-project` — removes the current project entry from the global registry.
- `--quiet` flag on `dreamd init` to suppress non-essential output.
- HTTP API on Unix domain socket: `POST /api/v1/learn`, `GET /api/v1/recall`, `POST /api/v1/dream`, `GET /api/v1/preferences`.
- MCP server (`dreamd mcp`) — `search_nodes` and `append_node` tools; Phase 1 in-process / Phase 2 UDS bridge.
- `SO_PEERCRED` peer-credential middleware on the UDS API (UID-match enforcement on Linux/macOS).
- `X-Agent-Root` header routing and per-user project registry at `~/.agent/registry.toml`; `dreamd init` registers each project automatically.
- Tantivy 0.26 full-text index with 5-second commit cadence; salience-aware recall collector (BM25 × exponential-decay × pain × importance × log-scaled recurrence).
- Episodic decay: events with score < 2.0 and age > 90 days are archived to `.dreamd/snapshots/YYYY-MM-DD.jsonl`, never deleted.
- Dream-cycle WAL at `.dreamd/dream_in_progress.wal`; startup recovers torn cycles before serving traffic.
- Recurrence sidecar at `semantic/recurrence_counts.json`; per-`skill_action` cluster counts drive promotion and the salience formula.
- Privacy disclosure printed on first run in any directory without an existing `.agent/` store.
- `npx dreamd-mcp` Node.js shim for zero-install MCP server distribution.
- Agent output redaction: high-entropy strings matching common token patterns are stripped from `content` before append on every path — the HTTP `POST /api/v1/learn` endpoint and the MCP `append_node` tool, both Phase 1 (in-process) and Phase 2 (daemon bridge).
- Criterion benchmark suite for recall latency (`cargo bench -p dreamd-core`).
- `rmcp 1.7.0` (MCP spec 2025-11-25) added as workspace dependency; consumed by `dreamd mcp` subcommand.
- GitHub Actions CI/CD pipeline: lint, test, cross-platform build, binary size gate (NFR-2), DCO sign-off check.
- Release workflow: cross-platform binary builds published to GitHub Releases on tag push.
- Initial project scaffold (Cargo workspace, `SPEC.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`).
- Per-project coordinator routing: each project's `.agent/` store gets its own isolated writer, so memory from one repo can't be misfiled into another.
- `--project-root` flag on `dreamd mcp`, letting IDE adapters pin the project store explicitly (fixes the agent-root mismatch seen in Cursor/Cline).

### Changed

- `AgentLearning.id` is now `EventId` (daemon-minted `evt_`-prefixed Crockford base32 ULID); clients no longer supply IDs — any inbound `id` is overwritten by the coordinator.
- Topology: `npx dreamd-mcp` auto-detects a running daemon and bridges over UDS (Phase 2); otherwise it runs an in-process server (Phase 1). `dreamd watch` provides the shared serialized writer for multi-agent setups.
- `skill_action` keys are normalized and validated to `[a-z0-9_]` segments joined by `::` (e.g. `rust::borrow_checker`); previously-tolerated `.` and `-` are now rejected.
- `dreamd dream` proxies to the running daemon over the Unix domain socket when one is live (running in-process only when no daemon is reachable), so a manual cycle can't race the daemon's writer.

### Fixed

- Dream cycle no longer orphans the coordinator's append file descriptor after the atomic `LESSONS.md`/JSONL renames; appends written during a cycle could previously be dropped.
- `npx dreamd-mcp <subcommand>` routing corrected.
- `dreamd watch` unlinks its Unix domain socket on `SIGTERM`, so a clean restart no longer trips over a stale socket.
- `dreamd init` refuses to scaffold a phantom `.agent/` store when no project-root sentinel is present, instead of leaving an orphan.
- macOS Unix-socket `sun_path` overflow when `$TMPDIR` is long.

### Security

- `~/.agent/` is created atomically at mode `0700` and `registry.toml` is stamped `0600`, closing the brief world-readable window during directory creation.
- `schema_version` is now server-stamped on the raw `POST /api/v1/learn` path (previously client-trusted).
